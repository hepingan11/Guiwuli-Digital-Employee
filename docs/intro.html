Workflow Chat —— 下一代开源数字员工操作系统

不是又一个用完即走的聊天机器人，而是可持续配置、可追踪、可审批的数字员工队伍。 核心不是"开发操作"，而是控制操作：理解目标、调用工具、等待人工审批、记录全过程。

01 / 创意介绍

想解决什么问题

现在的 AI 工作流要么是"用完即走"的一次性机器人，要么是把人完全排除在外、在高风险节点上自作主张的黑箱。 企业既想要自动化效率，又不敢把关键决策交给一个不可控、不可追踪、记不住事的 AI。

🎯

真正的痛点

不在"怎么让 AI 干活"，而在"怎么控制 AI 干活"。重要节点必须能由人确认，拒绝后流程可停止或进入其他分支。

💡

灵感来源

让每个人都能像管理团队一样，管理一支随叫随到的数字员工队伍，用极低成本组建 24 小时在线的团队。

🧩

产品形态

开源数字员工系统：Web 控制台 + 后端编排引擎 + 聊天软件集成 + 浏览器插件。Dify / Codex / MCP / n8n 都是它可调用的工具。

02 / 目标用户及痛点

面向谁，在什么场景

中小团队负责人、个人创业者，以及运营 / 客服 / 产品等需要把重复流程交给 AI、但又必须对结果负责的职能人员。

📢

运营场景

把文案和素材整理成规范输入，再触发 Dify 发布工作流，全程提示词可控。

🎧

客服场景

网页聊天中基于自有知识库实时给出回复建议，只展示、不自动发送，由人工采纳。

📱

老板场景

通过 Telegram / 微信 Bot 随时指挥和监控数字员工，在重要节点亲自点头或叫停。

如果没有这个产品，用户会遇到

  • AI 记不住上次干了什么，每一次都从零开始
  • 关键操作无人把关：要么全自动出事，要么全人工没效率
  • 多个工具各自为政，无法协同编排
  • 提示词散落各处，难以统一优化
  • 多个 AI 角色之间无法互相沟通协作，只能单枪匹马
03 / 价值与意义

效率提升 + 商业价值

把零散的 AI 调用，沉淀成可配置、可追踪、可审批、会成长的标准化数字劳动力。

⚡

效率提升

把"理解目标 → 整理输入 → 调用工具 → 人工审批 → 复盘记忆"做成标准链路。 每个员工拥有独立的 SQLite + Markdown 长期记忆，任务完成后自动复盘、提炼经验和避坑点，越用越聪明，且无需任何外部数据库服务即可本地运行。

💼

商业价值

作为开源数字员工 OS，它不替代现有生态，而是把 Dify、Codex、MCP、n8n 统一编排为"可被指挥的员工"， 大幅降低团队搭建自动化工作流的门槛和迁移成本。一条命令即可部署，真正让"每个人都能当老板"。

05 / 已支持能力

MVP 已经能做什么

围绕"控制操作"这一核心，已落地从编排到审批、从记忆到推送的完整闭环。

🛠 工具配置

Web 中创建 / 编辑 / 授权外部工具，v0.1 以 Dify Workflow 形态接入，可同步元信息、测试运行、按职位授权。

✅ 审批运行

Playbook 生成 Run 按步推进，工具节点执行、审批节点暂停，批准后继续、拒绝可停止或分支。

🧠 角色长期记忆

semantic / episodic / procedural / preference / pitfall 五类记忆，执行前注入相关经验。

🔔 消息集成

支持 Telegram Bot 与微信 Bot，随时指挥与监控；Claude Code、Coze、n8n 等正在路上。

运营发布控制链路

文案 + 素材 → 提示词规范化 → Workflow API Payload → Dify Workflow

06 / 核心亮点

为什么是 Workflow Chat

🤝

人在环路

Human-in-the-loop：审批节点可暂停、批准、拒绝，控制权始终留在人手里。

👥

多角色协作

多个角色在同一个"群"里互相沟通，知道彼此能做什么；预留 CEO 角色统计日志、追踪目标健康度。

🔒

安全优先

接口统一鉴权，插件须手动启用才捕捉消息，主动规避保存 cookie / token / password 等敏感字段。
